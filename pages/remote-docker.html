🌐 Remote Docker Mount (Same Network)

📋 Overview

Mount and manage Docker containers from other machines on the same network (10.1.4.x) through this portal.

Method: Portainer Agent (recommended) — install a lightweight agent on the remote host, then add it as an endpoint in Portainer.

🔧 Step 1: Install Portainer Agent on Remote Host 
# On the REMOTE machine (e.g., 10.1.4.x), run:
docker run -d -p 9001:9001 --name portainer_agent \
  --restart=always \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /var/lib/docker/volumes:/var/lib/docker/volumes \
  portainer/agent:latest

# Verify agent is running:
curl -s http://localhost:9001/ping
# Expected: {"status":"OK"}

Port 9001 must be accessible from 10.1.4.201

🔗 Step 2: Add Remote Host in Portainer
  1. Open Portainer :59009
  2. Go to Environments → Add environment
  3. Select Agent
  4. Enter: Name = descriptive name, Environment URL = 10.1.4.X:9001
  5. Click Connect

After connecting, the remote host's containers appear in Portainer alongside local containers.

🔌 Alternative: Docker TCP API (No Agent) 
# On the REMOTE machine, expose Docker API:
# Edit /etc/docker/daemon.json:
{
  "hosts": ["unix:///var/run/docker.sock", "tcp://0.0.0.0:2375"]
}

# Restart Docker:
sudo systemctl restart docker

# ⚠️ WARNING: TCP 2375 is UNENCRYPTED. Only use on trusted networks.
# For TLS, use port 2376 with certificates.

In Portainer: Environments → Add → Docker → tcp://10.1.4.X:2375

🔒 Security Considerations
  • Portainer Agent: Encrypted communication, recommended for production
  • TCP 2375: Unencrypted, only for trusted LAN (10.1.4.x subnet)
  • TCP 2376 + TLS: Encrypted, requires certificate setup on both sides
  • Firewall: Only allow agent/API ports from 10.1.4.0/24 subnet
  • Unified credentials: All remote hosts should use same admin958168 credentials
